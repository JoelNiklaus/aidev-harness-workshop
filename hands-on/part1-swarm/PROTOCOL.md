# Swarm evaluation protocol (Part 1 hands-on)

Goal: hundreds of attendees' coding agents fill a grid of Terminal-Bench 2.1 trials together; a live board shows results as they land. Everything runs on Hugging Face infrastructure.

## Components
- `coordinator/` — HF Space (Docker, FastAPI, one process). Owns the queue and the board.
- `runner/` — attendee CLI (`aidev-swarm`), run with `uvx` from a small package. Claims a cell, runs it with Harbor in an HF Sandbox under the attendee's own HF token, submits the result.
- `replay/` — pre-run results from existing Harness Leaderboard trials, loaded as the offline fallback and as the "reference" layer.

## Grid
`config/grid.json`: `{"model": "<HF router id of GLM-5.3-Flash>", "harnesses": [...], "tasks": [...], "trials_per_cell": K}`. A cell = (harness, task, trial_index). Task list comes from `config/tb21-subset.json`.

## Providers
`config/providers.json` is the one list of GLM-5.3-Flash providers the workshop uses, Part 1 and Part 2 alike: `{"model", "providers": [{"name", "weight"}]}`, today **novita (weight 3) and zai-org (weight 1)**. The list holds only providers the Harness Leaderboard's equivalence policy admits for the model (its `models.json` `equivalence`: zai-org is the reference, novita passed every criterion and is fp8 like it); baseten, together, coreweave, fireworks-ai and deepinfra are not admitted (precision differs, is unpublished, or the admission is pending), so they stay out even though they were clean at 240 simulated trials. The board's reference layer comes from leaderboard runs on zai-org (351 of 600 trials) and on the zai-org + novita pool (240), so a room split over these two compares with it as the leaderboard compares its own pooled trials. Weights 3:1: zai-org slowed down above 16 concurrent long-context agents on 14 Nov, Novita stayed flat up to 128.

Each attendee gets one provider: order the providers by `-ln(u) / weight`, smallest first, where `u = (int(sha256(lower(hf_user) + "\n" + provider)[:8 bytes], big-endian) + 0.5) / 2^64` (weighted rendezvous hashing; `runner/src/aidev_swarm/providers.py`). The first is the attendee's provider, the rest the fallback, in order. A provider is first for its share of the weights (75% novita), and dropping one moves only its own attendees. Check values for the list above: `alice` -> novita, zai-org; `dave` -> zai-org, novita; `JoelNiklaus` -> novita, zai-org.

Fallback. Runner (`aidev-swarm` >= 0.4.1): each trial runs on the attendee's current provider. Inside the trial the leaderboard's meter sends a call that novita answers with 429 on to zai-org (the leaderboard's own rule, logged per call); a trial whose provider answered 3 or more calls with 429/5xx, or that ended before any model call, moves the attendee's next trials to the next provider. `check` tries the next provider on 429/5xx. A `provider` in the claim's `run_config` overrides the choice for everyone (an emergency switch; `grid.json` sets none). Part 2 (`aidev-evolve`) calls the router itself and falls back per call (`../part2-evolve/REQUESTS.md`, `../part2-evolve/PROTOCOL.md`).

## HTTP API (coordinator)
Auth: every POST carries `Authorization: Bearer <attendee HF token>`; the coordinator calls `https://huggingface.co/api/whoami-v2` once per token (cache it) and records the username. Never store or log tokens.

- `POST /api/claim` → `{"cell_id", "harness", "task", "trial", "model", "lease_expires_at", "run_config": {...}, "share"}` (one cell per claim) or `204` when nothing is left. Atomic (single process + SQLite). Claims need `User-Agent: aidev-swarm/<version>` with version >= 0.4.3, else `426` (runners before 0.4.0 heartbeat too rarely for the short lease; 0.4.0 does not spread over providers; up to 0.4.2 an agent whose time was up was not stopped and could keep working while the tests ran). Lease 90 s, renewed by heartbeats (below); an expired lease returns its cell to the queue at its place in the order. Expiry is lazy: every claim and every state read treats a lease past its expiry as free (no sweeper). When no cell is free: `204` with `Retry-After: 30` while leased cells remain (one may come back), plain `204` when every cell has a result (stop). Harness order in `grid.json`: Pi, OpenCode, OpenClaw first; then the remaining 7 sorted by expected trial duration/cost, longest and most expensive first (they need the most time to finish). Order: one harness after the next, in the order of `grid.json` `harnesses` — all cells of harness 1 are handed out before any cell of harness 2. Within a harness, breadth-first over trials (every task gets trial 0 before any gets trial 1). The grid holds 10 harnesses; the room may not reach all of them, and the board shows only harnesses with results (plus "not reached" for the rest). Lease limit: `?limit=L` (default 1, at most 9) lets the user hold up to L live leases, capped by their `share`: the cells without a result spread over the active attendees (a lease, or a claim or heartbeat in the last 270 s), and a slow start of 2 leases plus one per 20 s since the user's first claim, so the first arrivals do not take every cell before the room is seen. A runner with `--parallel N` (default 8 for `launch`) runs N slots, each claiming with `limit=N` (N+1 while it skips a failed cell or another Job of the user holds a lease); slots beyond the last `share` the coordinator named wait without asking, the slot at it asks with a backoff (30 s doubling to 300 s), so a full room's Jobs leave their extra slots idle.
- `POST /api/heartbeat/{cell_id}` → extends the lease by 90 s. The runner beats every 24-30 s (random within that, so runners do not beat in step) from a background thread, independent of the agent: a live trial keeps its cell however long it runs and survives two lost beats; the cell of a runner that dies without a word (SIGKILL, lost node) returns about 90 s after its last beat. A beat on an expired lease that nobody took over renews it. Rate: 500 runners send ~19 heartbeats/s, below the ~30 req/s from one IP that the HF edge took without a 429.
- `POST /api/submit/{cell_id}` body = Result (below) → `200`. Rejects (409, logged as a late result) if another user holds the cell, typically because the sender's lease expired and the cell was claimed again; accepted if the lease expired but nobody holds the cell now. Exactly one result per cell. Writes the result JSON to the results bucket/dataset and to SQLite.
- `POST /api/release/{cell_id}` → gives a cell back. The runner releases its held cells on every way out it can catch: crash, Ctrl-C, SIGTERM (Job cancel or timeout; only the first SIGTERM interrupts, so a second cannot cut the release short), and an exit hook; on the way out it tries for at most 6 s, then the lease expires on its own. A coordinator restart gives every saved lease a fresh 90 s, so live runners keep their cells.
- `GET /api/state` → grid fill counts, per-(harness) aggregates, recent results (for the board, polled every 3–5 s; cache 2 s).
- `GET /` → live board: (1) leaderboard table per harness: pass rate with CI, trials, cost per trial, cost per pass, tokens per trial; (2) grid fill view (harness × task, cells colored claimed/pass/fail); (3) Pareto plot cost per trial (log x) vs pass rate, room results next to the reference layer; (4) feed of the newest results with usernames. Readable on a projector: large type.
- `GET /join` → the copy-paste page the slide's QR code opens: install uv, token permissions, `uvx hf auth login`, the agent prompt and the launch command, each with a Copy button; a link back to the board. Built from `runner/README.md` (wheel URL) and `runner/AGENT_PROMPT.md`; no auth header needed.

- `GET /evolve/join` → the Part 2 start page on the board (the attendee site's static page `/2` shows the same commands and does not open this one): `aidev-evolve check`, one run command per seating block (`run --block left|middle|right`, a switch between Claude Code and Codex), `show`, `replay`, each with a Copy button. The wheel URL is the `<WHEEL_URL>` line of `../part2-evolve/README.md`; the blocks are a copy of `aidev_evolve.strategy.BLOCKS` (a test compares them).
- `GET /api/versions` → `{"aidev-swarm": "0.4.3", "aidev-evolve": "0.6.0"}`: the oldest clients the board takes (the frozen workshop versions). `POST /api/claim` from an older runner and `POST /api/evolve/submit` from an older aidev-evolve (or without its `User-Agent: aidev-evolve/X.Y.Z`) get `426`. aidev-evolve asks this endpoint at the start of a run and warns when it is older.
- Room settings (Space variables, `deploy --coupon-part1 <link> --coupon-part2 <link> --trials-per-cell N`): each session's shared coupon link appears above step 1 of its start page; `SWARM_TRIALS_PER_CELL` (3 to 10) enlarges the grid beyond grid.json's trials per cell.
- Load-test names (staging only, `deploy --target staging --loadtest-users <account>`): a request of an allowed account with the header `X-Aidev-Loadtest-As: lt-<name>` acts as the user `lt-<name>` (own share, slow start and rate limit), so one account can stand in for a room (`coordinator/scripts/room_loadtest.py`). Other accounts and the workshop Space answer `403`; a deploy without the flag removes the setting.

## Result (JSON)
```
{"cell_id": str, "harness": str, "harness_version": str, "task": str, "trial": int, "model": str,
 "reward": float, "passed": bool, "started_at": iso, "finished_at": iso, "wall_s": float,
 "n_input_tokens": int, "n_cached_tokens": int|null, "n_output_tokens": int, "n_calls": int|null,
 "cost_usd": float, "error": str|null, "hf_user": str, "runner_version": str,
 "sandbox_id": str|null, "trajectory_url": str|null,
 "provider": str, "n_provider_errors": int}
```
`provider` = the provider the trial was routed to (Providers above); `n_provider_errors` = its calls answered 429/5xx (from the meter log). Both are optional for the coordinator (0.4.0 runners send neither); `/api/state` counts results per provider (`counts.by_provider`) so the board and the analysis can split by it.
`cost_usd` = tokens × the provider list price in `config/prices.json` (same numbers on board and slides).

## Runner UX
`uvx --from <wheel url> aidev-swarm check` tests an account before the workshop (one model call, one tiny HF Job, one sandbox command; claims nothing). `aidev-swarm launch [--n K] [--parallel N]` submits one HF Job in the attendee's namespace that runs `aidev-swarm run --loop | --n K --parallel N` (N trials at once, default 8, each in its own HF Sandbox): it claims, runs the trial, heartbeats, submits and prints the board URL. `run --dry` checks token and credits and claims nothing. A one-paragraph prompt for the attendee's coding agent ("run this, watch it, report the result") lives in `runner/AGENT_PROMPT.md`.

## Rules
A claim beyond the user's lease limit or share returns 409 with `held` (cells already held) and `share`; cell ids are `<harness>__<task>__<trial>`; bad requests 422; Hub outage during auth 503. The HF edge rate-limits per IP (429 after ~870 fast requests): runners keep unsent results and retry for at least 30 min; the board polls every 10 s with backoff.

Development: every test fakes the external calls (Hub, Jobs, sandboxes, model) and the suites run in seconds. Tokens never appear in logs.

### Second round (live mode)
Free base trials take priority. When all remaining base trials are leased, the coordinator allocates unique repeat trials. Within each repeat wave it tries the shortest observed harness/task pairs first. New claims stop 18 minutes after the first claim; running trials can still submit. The board shows base completion and extra results separately. Both count toward the room scores; the reference stays fixed. Replay uses only the base grid.
